# Windows: PROXY, VPN и переключение сервера

Редакция 2026-10-18; локальный кандидат 0.1.0+19. Это описание реализации,
не завершённая приёмка E1 или стабильный выпуск.

Установщик +19 применён с exit0 после подтверждённого пользователем отключения.
Установленные EXE/AOT/service совпали с пакетом; приложение открыто, служба Running.
[Проверки, сборка и границы](evidence/windows-proxy-build19.json).

## Поведение

Под кнопкой подключения расположен выбор PROXY / VPN. В отключённом состоянии
он выбирает следующий режим. В подключённом состоянии смена режима или сервера
передаётся одной командой `reconnect`; повторные нажатия во время операции
блокируются. Нативное состояние определяет активный сервер, режим и таймер.
При отказе нет имитации успешного соединения.

VPN использует прежние TUN, DNS, исключения и WFP. При смене VPN-сервера
принадлежащая ExVPN блокировка сохраняется между остановкой старого и запуском
нового ядра. Переход VPN → PROXY снимает её только после чистого закрытия TUN;
восстановленный после аварии guard или ошибка очистки запрещают такой переход.

PROXY открывает только loopback HTTP endpoint с CONNECT через выбранный профиль.
Служба проверяет настоящий HTTPS через этот endpoint перед состоянием connected.
TUN, системные маршруты/DNS и WFP в этом режиме не создаются. Приложения,
использующие пользовательский системный прокси Windows, получают эту настройку;
полный захват трафика, исключения приложений и kill switch относятся к VPN.
Локальный HTTP endpoint не требует proxy-auth для совместимости с системными
настройками: любой локальный процесс может подключиться к этому loopback-порту.
Контрольный IPC по-прежнему проверяет SID и точный защищённый путь EXE.

## Пользовательские настройки Windows

C++ bridge работает от обычного пользователя и использует WinINET per-connection
API для LAN-настроек. Предыдущие flags, proxy, bypass и PAC сохраняются в
HKCU под DPAPI до изменения; журнал содержит только фиксированный loopback
endpoint службы и прежние настройки. Подписка не задаёт эти параметры.
Ссылки на API: [Internet options](https://learn.microsoft.com/en-us/windows/win32/wininet/setting-and-retrieving-internet-options),
[option flags](https://learn.microsoft.com/en-us/windows/win32/wininet/option-flags).

Опрос состояния не захватывает новые настройки без сохранённого владения или
явного подключения PROXY. Ручное изменение Windows/другим приложением не
перезаписывается. При отключении восстанавливаются только настройки, которыми
ещё владеет ExVPN. При переходе PROXY → VPN восстановление откладывается до
подтверждённой блокировки VPN, чтобы ошибка остановки не давала прямой обход.
Если служба недоступна, сохранённый журнал даёт интерфейсу действие отключения
для локального восстановления. Повреждённый журнал не заменяется пустым.
Машинная политика `ProxySettingsPerUser=0` не обходится.

Обычный выход из UI не останавливает службу или активный PROXY. Перед upgrade/
uninstall нужно явно отключиться: установщик отказывается обслуживать пакет,
пока в профиле владельца есть proxy lease. Это сохраняет пользовательские
настройки и не требует их расшифровки от другого административного аккаунта.

## Проверка и оставшиеся границы

- 34 Dart controller/codec checks: сериализация, одинаковый сервер, занятые
  команды, ошибки, режимы и восстановление при недоступной службе.
- Native Windows unit, focused race и vet прошли. Независимый локальный VLESS
  peer подтвердил HTTP forward и HTTPS CONNECT, счётчики и закрытие listener;
  неверный TLS trust и недоступный сервер не приводят к прямому запросу.
- 11 C++ сценариев с fake backend проверили PAC/bypass/flags, смену endpoint,
  ошибки записи/применения/восстановления и отказ захватывать чужие настройки.
  Эти проверки не меняли настройки сети хоста.
- Реальное применение WinINET к Windows-профилю, полный цикл установленной
  службы PROXY ↔ VPN, аварии/upgrade/uninstall в этих режимах ещё требуют
  отдельной приёмки. Full runner и новая системная VPN-матрица не запускались.
- Android сохраняет прежний VPN-only контракт; PROXY и атомарное переключение
  сервера пока объявляются неподдерживаемыми на этой платформе.

Светлая тема этой редакции — бело-голубая: белая кнопка, серый символ OFF,
голубой символ и свечение ON. Тёмная палитра сохранена. Строки серверов разделены
небольшими вертикальными промежутками; закреплённая шапка не прокручивается.
