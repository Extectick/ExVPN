# Граница проверки локального TLS-стенда

2026-10-17, установленный Windows +6 в одноразовом Sandbox. Исследовательский
прогон добавил Trojan и Hysteria2 с краткоживущим локальным CA. CA был временно
добавлен **только в гостевой** LocalMachine Root, без изменений хоста.

Семь прежних вариантов прошли. Обе TLS-записи остались `blocked` /
`tunnel_unreachable`, счётчики не выросли. Положительная проверка Trojan/Hy2 не
состоялась. Проверка неправильного SNI не была достигнута и не отмечается пройденной.

В закреплённом Xray выбор `UseSystemCa=false` использует встроенный набор CA;
добавление корня Windows не меняет его доверие. Это объясняет отказ данного
подхода к стенду; производственная TLS-политика не изменена. Экспериментальная
установка CA и её исходники убраны из активных QA-скриптов, локальная копия
сохранена в игнорируемой `.private/`.

Удаление принадлежащего стенду CA прошло; проверка отсутствия корня и fingerprint
всего Root store совпала с исходной. Второй cleanup-вызов сначала не принял уже
восстановленный production binding. Исправлен идемпотентный `guest-app-qa Restore`:
он допускает только точный QA либо production command из защищённого состояния,
с прежними проверками LocalSystem и хеша службы. Повтор Restore/Finish прошёл;
маршруты/DNS восстановлены, TUN/guard отсутствуют, production service работает.
Исходный неуспешный отчёт не переписан задним числом успешным.

Этот отрицательный результат не закрывает E1-005. Core-level TLS-тесты с
test-only trust также не подменяют положительную проверку установленного клиента.
Исходники исправления cleanup: [8fa4b5d](https://github.com/Extectick/ExVPN/commit/8fa4b5dbb4545894e26617c91a5bba1bb284e9f2).
