# Android: проверка нативного клиента

Дата: 2026-10-16. Рабочее дерево; commit ожидается. Это ограниченная проверка
эмулятора, **не закрытие E1/E4 и не готовность стабильного выпуска**.

## Стенд и сборки

Android 16/API36, x86_64, эмулятор Pixel 4a с WHPX. Стенд запущен read-only,
без загрузки/записи snapshot. Маршруты, DNS и firewall Windows-хоста не менялись.
Физическое Android-устройство и минимальная ОС Android11 не проверены.

Debug APK содержит arm64-v8a и x86_64 JNI; размер каждой указанной сборки
243247462 байта. APK подписан отладочным ключом и не является release-пакетом.

## Метод

Синтетический VLESS TCP сервер работает только на loopback хоста; эмулятор
обращается к нему через штатный шлюз Android Emulator. Реальная пользовательская
подписка не использовалась. Два собственных QA APK имеют разные UID: защищаемый
и выбранное исключение. Код находится в `scripts/qa/android-https-probe`.

Probe использует обычное системное соединение, проверяет HTTPS-сертификат и имя,
не привязывает сеть и не обходит VPN. В результатах только HTTP status, время,
счётчики, признак VPN transport и SHA256 ответа. Внешний IP проверяется на
корректный числовой формат, исходный ответ не сохраняется. UID TrafficStats
может запаздывать; нулевой счётчик не трактуется как отсутствие трафика.

Хостовый сервер и эмулятор имеют общий внешний выход. Поэтому равные внешние IP
не доказывают путь через прокси. Исключение проверено контролируемой остановкой
сервера и одновременными запросами двух UID, а туннель — также счётчиками Xray.

## Результаты

| Сценарий | Наблюдение |
|---|---|
| Разрешение VPN | Настоящий Android Connection request подтверждён на стенде |
| Независимый HTTPS через TUN | Health204; IPv4/IPv6 endpoints200; numeric HTTPS200; VPN transport=true |
| DNS доступность | Получены 2A+2AAAA; это проверка доступности, не аудит утечки DNS |
| Состояние UI | Connected только после native HTTPS health; реальные счётчики увеличиваются |
| Сохранение подписки | Импорт через UI и force-stop/cold launch сохранили группу и выбранный профиль |
| Исключение | В UI выбран только второй QA package, основной остался защищаемым |
| Остановка сервера | Защищаемый numeric HTTPS завершился ошибкой8055ms; исключённый одновременно получил200 за587ms; TUN оставался |
| Отказ IPv6 | При остановленном сервере защищаемый IPv6 hostname достиг18s deadline без успешного fallback |
| Восстановление сервера | Без повторного Connect UI восстановился; защищаемый HTTPS204 |
| UI в фоне | Независимый HTTPS продолжил работать |
| Wi-Fi→cellular→Wi-Fi | После подтверждённой смены underlying network HTTPS204 на обеих сетях |
| Сохранение исключений | Native policy пережила force-stop/cold launch; выбранный package остался отмечен |
| Always-on | После включения в системном UI ОС восстановила зашифрованный принятый сеанс; HTTPS204 |
| Авария без OS lockdown | TUN исчез; обычная сеть доступна. Это граница Android, не успешная защита |
| Авария с OS lockdown | После SIGKILL собственного процесса оба UID сразу получили сетевую ошибку при отсутствии TUN |
| Автоперезапуск процесса | **Не подтверждён:** процесс не восстановился несколько минут, несмотря на START_STICKY |
| Повреждённый resume | Только синтетический encrypted resume усечён до7B после смерти процесса. При OS start создан блокирующий TUN, HTTPS отказал; UI показал native_storage_unavailable |
| Явная отмена | Resume удалён; policy и подписка сохранены. При оставшемся OS lockdown сеть остаётся заблокирована системой |
| Start после отмены | OS Always-on OFF/ON не воскресил старый сеанс: блокирующий TUN и profile_required; HTTPS отказал |

После lifecycle QA системные Always-on/Block выключены через Settings UI,
служба остановлена, обычный numeric HTTPS снова вернул200 без VPN transport.

## Воспроизведение незакрытой аварии

На этом API36 AVD подключить синтетический профиль, включить Always-on и Block
connections without VPN в системном UI, остановить контролируемый прокси.
Получить PID только ExVPN и отправить ему SIGKILL через `run-as`; не использовать
`am force-stop`. До переключения Settings проверить service record и отдельные
probe APK. Сеть блокируется ОС, но процесс автоматически не восстановился.
В системном событии наблюдался DeadObjectException при VPN interface removal и
unbind. Это корреляция, а не доказанная причина в Android framework.
Обходы через alarm/job не добавлены.

## Незакрытые границы

- Физический Android11+ и минимальная ОС; API30 image отсутствует, новая лицензия
  автоматически не принималась.
- Пользовательский провайдер и полный Android protocol matrix.
- Полный IPv4/IPv6/DNS packet-capture аудит с холодным DNS cache; edge cases
  неизвестного/shared UID и lifecycle установленных приложений.
- Автовосстановление после SIGKILL, reboot/unlock, sleep/resume и обновление пакета.
- Подписанный release, installer, OTA и полный набор лицензий/SBOM.

Все ограничения остаются открытыми в CHECKLIST.md.
