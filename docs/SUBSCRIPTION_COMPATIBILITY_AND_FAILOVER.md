# Совместимость подписок и основной/резервный сервер

2026-10-20. Исходники: `1d99998`; установленный клиент не обновлялся.
Версия базы остаётся 0.1.8+29. Native-изменения требуют следующей полной
Shorebird-базы, а не Dart-патча для существующей базы.

## Принятое поведение

Из Xray JSON извлекаются нормализованные серверные профили. Дополнительно
разрешены `sockopt.tcpKeepAliveIdle` и `tcpKeepAliveInterval`: целые секунды
1–86400. Пустой `tcpSettings: {}` нормализуется; непустой отклоняется.
Локальные mark/interface/bind/dialerProxy, произвольные socket options и
параметры маршрутизации провайдера не передаются ядру.

Hiddify/sing-box JSON распознаётся по `outbounds[].type`. Поддержаны
показанные VLESS TCP/REALITY, XHTTP/REALITY, WebSocket/TLS и Hysteria2/TLS,
`server_port`, `tls.server_name`, uTLS fingerprint, REALITY public key/short ID,
ALPN строкой или списком, `packet_encoding: xudp` для VLESS и WS marker
`Sec-WebSocket-Protocol`. Перевод строго типизирован: это не выполнение
произвольной sing-box конфигурации. Некорректные TLS-параметры и insecure
не становятся поводом отключать проверку сертификата.

`0.0.0.0:1` из примера «переустанови приложение» — заглушка, не рабочий
сервер. Она отклоняется. Название профиля никогда не исполняется как инструкция.
Неподдерживаемые direct/blackhole outbounds пропускаются; доверенные локальные
DNS, маршруты и блокирующие outbounds ExVPN создаёт самостоятельно.

## Автоматическая группа

В раскрытой подписке с 2–32 серверами есть строка «Авто · основной и резерв».
Она включается пользователем; provider JSON не может включить её сам.
Серверы проверяются по порядку списка. Первый с успешным HTTPS становится
активным; последующий транспортный отказ приводит к следующему серверу.
После неудачного полного обхода — пауза 30 секунд. Здоровое соединение
сохраняется: нет постоянного переключения из-за небольших изменений TCP ping.
Группы больше 32 не усекаются молча: автоматическая строка недоступна.

Это **локальная политика primary/backup**, не реализация алгоритмов
`leastLoad`/`roundRobin` из присланных `routing.balancers`. `burstObservatory`
и его HTTP-адреса не управляют проверками ExVPN. Принимаются серверы этих
конфигураций, но их глобальная семантика не воспроизводится целиком.

Windows-группой управляет служба, Android-группой — VpnService; закрытие UI
не останавливает переключение. На Windows группа живёт в памяти службы;
её авария не означает разрешение прямого выхода, persistent guard сохраняется.
Android хранит группу в зашифрованном resume record v3, читает прежние v1/v2.
Общий защищённый снимок подписок v3 читает прежние v1/v2 и сохраняет выбор
«Авто», но восстановление UI само по себе не запускает VPN.

Смена режима Windows PROXY/VPN сохраняет автоматическую группу. PROXY по-прежнему
охватывает только приложения, соблюдающие системные proxy settings; защита TUN
и WFP относится к режиму VPN. Выбор отдельного сервера отменяет группу.
Отмена только автоматической политики сохраняет текущее соединение.
Обновление подписки не подменяет активный снимок группы: новые участники
применяются после явного выбора/переподключения. Удаление активного участника
отключает дальнейший автоматический перебор без снятия действующей защиты.

## Граница безопасности

Группа передаётся через существующий аутентифицированный native bridge
полем `automaticProfiles` в connect/reconnect. Максимум 32 уникальных ID,
суммарный native frame остаётся ограниченным. Каждый профиль проверяется
закреплённым ядром до принятия команды; выбранный профиль обязан полностью
совпадать с соответствующим членом группы. Совпадения одного ID недостаточно.

При Windows VPN→VPN используется существующая атомарная замена с persistent
deny guard; `Disconnect` для переключения не вызывается. Android останавливает
ядро, сохраняя тот же TUN. Неизвестный владелец приложения не становится
исключением. Транспортные отказы допускают перебор; ошибки конфигурации,
protect/guard, хранения, доступа и неизвестные ошибки его останавливают.
Отмена, ручной выбор и disconnect инвалидируют устаревшие попытки.
Ни исчерпание группы, ни отказ DNS не включают direct fallback.

## Проверки и незакрытая приёмка

Три приватных Xray-примера: **27/2/1** VLESS-записей импортируются и проходят
native Decode/Compile **30/30**. Первый содержит 12 повторов; список содержит
15/2/1 уникальных профилей. Реальный HTTPS через изолированный loopback SOCKS
проверен для 18 уникальных записей: **4 успешных HTTP204 в первом примере**,
остальные 14 — `probe_connection_failed`. Это не доказательство неверных
учётных данных или причины отказа сервера: такие соединения рабочими не отмечены.
Сетевые настройки хоста не менялись.

Новые Hiddify-примеры проверены синтетическими эквивалентами без реальных
секретов; это не live-проверка четырёх новых учётных записей. Host необходимо
передавать корректной JSON-строкой с обычной точкой, например `www.yandex.ru`;
невалидные JSON escape-последовательности не исправляются молча.

Unit-проверки покрывают нормализацию, неверные типы/полномочия, хранение,
первоначальный отказ и потерю рабочего сервера, запрет Disarm, отмену/epoch,
паузы, сохранение режима и восстановление UI. C++ bridge скомпилирован отдельно.
Kotlin проходит host typecheck против API36/Flutter/Androidx и 5 policy tests;
заглушка resource ID означает, что это **не APK/resource-link проверка**.

Один Full прогон: 11 lanes PASS, app остановлен анализатором на двух
отсутствующих блоках вокруг `if`. После исправления полностью повторён
только app lane: analyzer clean, **398 tests PASS**. Неизменившиеся 11 lanes
не повторялись. Отдельно после review добавлен `@Volatile` для публикации
Android policy; итоговый Kotlin host typecheck PASS. Это составной результат,
не утверждение о втором успешном едином Full на финальном снимке.

До выпуска нужны новая базовая native-сборка и изолированная runtime-приёмка:
Android/Windows основной→резерв при остановке сервера и закрытом UI,
исчерпание группы, IPv4/IPv6/DNS и приложение-исключение во время замены,
смена сети и отмена подключения. Физический Android и общая стабильная
приёмка E1 остаются открытыми. Подробности проверок — в CHECKLIST и evidence.
