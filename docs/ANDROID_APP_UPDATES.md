# Полные обновления Android

Кандидат **0.1.5+26**, 2026-10-19. До этого опубликованные ordinary APK получали
`DisabledFullUpdatesBackend`; Shorebird в них также недоступен. Это была
недостающая реализация, а не подтверждённая ошибка сети. Старым установкам нужен
один ручной переход на новый APK, чтобы появился механизм проверки APK updates.

## Проверка и загрузка

`AndroidFullUpdatesBackend` проверяет фиксированный `android-beta/android.json`
в release этого репозитория. Trust config — `config/updates/android-beta.json`.
Envelope содержит schema/keyId/payload/signature. Ed25519 подписывает точные байты
`ExVPN/android-update/v1\0` + payload. Windows использует другой domain и platform;
его manifest не принимается Android. Ключ подписания хранится только в CI/.private.

Payload содержит schema, appId, platform=android, channel, SemVer, build,
publishedAt/expiresAt, minSdk и asset(url/sizeBytes/sha256). Вход ограничен,
дубли/неизвестные поля и неверные типы отклоняются. Срок — до 30 дней, build
возрастает, SemVer не уменьшается. Сохранённый проверенный offer предотвращает
откат к ранее виденному меньшему выпуску. Публичная ссылка указывает точно на
соответствующий immutable APK; редиректы и HTTPS ограничены.

APK до 512 MiB сохраняется во временный файл приватного cache, проверяется
размер/SHA-256 и атомарно переименовывается. Неверная подпись, прерванная загрузка
или отмена не разрешают установку. Подготовленный файл проверяется повторно;
повреждённый файл требует загрузки, а не бесконечного повтора установки.

## Установка и состояние приложения

Канал `exvpn/app_updates` не принимает URL, путь, ключ или provider-конфигурацию.
Native возвращает текущую версию/build/SDK и фиксированный private cache.
Запрос install содержит только ожидаемые version/build/sha256. Native самостоятельно
выбирает файл, проверяет тип/путь/хеш, PackageManager identity, совместимость,
возрастание версии и единственный release signer. Сертификат должен совпасть как
с установленным APK, так и с закреплённым SHA-256 release-ключа ExVPN.

Установка требует отключённого ExVPN и отсутствия pending/native service.
Перед handoff сохраняются подписки/оформление; неявного disconnect нет.
Если Android ещё не разрешил этому приложению устанавливать пакеты, открываются
настройки именно ExVPN, а UI предлагает разрешить установку и повторить.

FileProvider публикует только `cache/app-updates/`. Проверенный системный
установщик получает временное разрешение чтения одного content URI. Открытие
его окна означает `installerOpened`, **не installed**. Android всегда требует
подтверждения пользователя; silent install и автоматический foreground reopen
не обещаются. UI не завершает себя и не сохраняет вечную блокировку команд:
отмена оставляет готовый пакет для повтора. Успех подтверждается новой версией
PackageManager после установки и обычного запуска.

## Публикация и границы проверки

Оба feed публикует один ограниченный script с Target Windows/Android после
immutable version release. Общий Ed25519 key используется с разными domain/
platform; signer не принимает APK для Windows или EXE для Android. Source
config и trust constants проверяются вместе с тестами. Публикуется beta,
стабильная приёмка E1/E6/E7 учитывается отдельно.

Unit/JVM проверяют отказы и lifecycle. Настоящее системное обновление со
сохранением данных в эмуляторе и физический Android — самостоятельные runtime
gates, не заменяются успешной компиляцией. Для будущего Google Play-выпуска
необходима отдельная политика доставки/разрешения установки пакетов.
