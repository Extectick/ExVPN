# Защищённые подписки

Реализация 2026-10-16, рабочее дерево; commit ожидается. Это компонент E3,
не подтверждение полной готовности VPN или приёмки физического устройства.

`SubscriptionStore()` в Flutter предоставляет `load(): Future<AppController>`
и `save(AppController): Future<void>`. Ошибки имеют только код
`SubscriptionStoreException.code`; данные, исходные исключения и URL не выводятся.
`supported` разрешает Android/Windows. Web и остальные платформы не сохраняют
секреты, пока для них не добавлена и проверена отдельная реализация.

Снимок v1 содержит нормализованные профили, выбранный сервер/группу, раскрытие
групп, коды ошибок, HTTPS sourceUrl и updatedAt UTC. Исходные подписки и
произвольные конфигурации провайдера не сохраняются. Размер JSON ограничен
8 MiB, 100 группами, 5000 профилями на группу и 10000 всего; глубина JSON до 32.
DEMO-профили не входят в снимок. Неизвестная версия/поля и неверные типы дают
ошибку, а не молчаливое удаление. UI не должен автосохранять пустой контроллер
поверх данных после ошибки загрузки.

Android: закреплён `flutter_secure_storage 11.2.0`, AES-GCM с RSA-OAEP ключом
в Android Keystore. `resetOnError: false` запрещает автоматическое стирание;
миграция шифра с зашифрованной резервной копией разрешена. Автоматический backup
и device-transfer данных приложения исключены в Manifest/XML.

Windows: собственный узкий backend вызывает current-user DPAPI через `win32
6.4.0`. Шифрованные записи находятся в каталоге Application Support ExVPN.
Сначала записывается и flush-ится временный **шифрованный** файл, затем выполняется
same-volume MoveFileEx с REPLACE_EXISTING/WRITE_THROUGH. Исходники Windows-плагина
4.2.2 проверены: он шифрует DPAPI, но перезаписывает один файл всех ключей с
усечением; этот путь здесь не используется. Несколько одновременных
процессов-писателей этим прототипом не поддерживаются.

Журнал: новая полная запись `pending`, проверка чтением, замена `current`,
проверка чтением и удаление `pending`. Операции одного store последовательны.
При прерванной замене current восстанавливается валидный pending; при
повреждённом pending остаётся предыдущий current. `recovered` сообщает об этом
выборе. После успешного удаления подписки в обоих ключах отсутствует старый
снимок, поэтому удалённые записи не воскресают при перезапуске. Сохраняемая
копия фиксируется в момент вызова save, а не в момент выполнения очереди.

Проверено: round-trip всех полей, выбор/группы/диагностика, защита источника при
ошибке обновления, удаление источника при ручной замене, ограничения схемы,
порядок конкурентных сохранений, искусственные обрывы обеих фаз, ошибка backend
без plaintext fallback. Реальный Windows DPAPI тест проверяет шифротекст,
повторное открытие, замену, tamper rejection и удаление. Android cold start с
настоящим backend проверен в эмуляторе API36; удаление и аварийное
завершение процесса проверяются в отдельном стенде;
отключение питания и повреждение носителя не объявляются проверенными.

## Native Android: восстановление службы

`VpnPersistence.kt` отдельно хранит выбранные package names и последний принятый
сеанс: AES-256-GCM, разные Android Keystore aliases для policy/resume, новая
случайная nonce на каждой записи и AAD с назначением записи. Секреты записываются
только шифротекстом в `noBackupFilesDir` через `AtomicFile`, с fsync и сверкой
сохранённых байтов. Все операции сериализуются одним process lock; backup и
device transfer отключены. Повреждённые данные или потеря ключа не сбрасываются
в пустое состояние автоматически.

Служба повторно валидирует сохранённый профиль и актуальные package UID перед
запуском ядра. При отсутствии/ошибке записи остаётся блокирующий TUN с явной
ошибкой. Явное отключение сначала останавливает ядро, затем удаляет resume;
неудачное удаление сохраняет блокирующий TUN до повтора. Изменение исключений
при остановленной службе также отменяет прежнюю resume-запись, чтобы старые
исключения не восстановились позднее. Системный отзыв разрешения уже снимает
маршрутизацию ОС; приложение не выдаёт отозванный TUN за действующую защиту.

Это не заменяет Android Always-on/Block connections without VPN: они нужны для
защиты между смертью процесса и восстановлением службы. Runtime-проверка новой
реализации, включая реальную Keystore и аварии, ведётся отдельно от Dart journal.
2026-10-16 на API36 эмуляторе подтверждены сохранение policy после cold start,
восстановление принятого профиля системным запуском Always-on и fail-closed при
повреждённом resume. Явное отключение удаляет resume и сохраняет policy; следующий
системный старт без нового Connect показывает `profile_required` и удерживает TUN.
После SIGKILL системный lockdown заблокировал оба тестовых UID, но автоматический
перезапуск службы за две минуты не наблюдался. Защита и автоматическое восстановление
учитываются отдельно. Физическое устройство, reboot и Android11 ещё не проверены.
API: [AtomicFile](https://developer.android.com/reference/android/util/AtomicFile),
[KeyGenParameterSpec](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec).
