# Импорт подписки из QR

Состояние на 2026-10-16: QR читается из выбранного пользователем PNG/JPEG через
системный выбор файла Android/Windows. Камера и live scanning пока не реализованы.

В диалоге добавления подписки кнопка **«QR из изображения»** открывает выбор файла.
Результат появляется в поле для проверки. HTTPS выбирает режим ссылки; остальные
данные — режим текста. Чтение QR не обращается по найденному адресу и не меняет
подписки. Импорт выполняется существующим парсером/HTTPS-loader только после
кнопки **«Добавить»**. Отмена выбора или ошибка оставляет введённые данные.

Ограничения: 5 МиБ с проверкой до и во время чтения; общий deadline 20 секунд на
metadata и полный поток уже выбранного файла; PNG/JPEG по сигнатуре;
каждая сторона не больше 4096 пикселей, суммарно не больше 4 Ми-пикселей;
один кадр; результат не больше 8192 символов, без NUL. Размеры проверяются
`ImageDescriptor` перед декодированием пикселей Flutter engine. Прозрачность
композируется на белый фон. ZXing читает обычный и инвертированный вариант;
на native декодирование QR выполняется через `compute`. Не больше 128 кандидатов
finder-pattern допускается до перебора троек ZXing: решётка ложных маркеров иначе
вызывает кубический рост работы даже на маленьком PNG. Превышение лимита выдаёт
«Изображение слишком сложное» без повторной инвертированной ветки. Ограничения
входа/растра/кандидатов не являются изоляцией нативного image codec или жёстким
таймаутом его CPU. Сам системный file picker остаётся под управлением пользователя.
При таймауте чтения stream отменяется без ожидания потенциально зависшего
provider cancellation; поздние события игнорируются, накопленный буфер очищается.

Ни имя файла, ни содержимое QR, ни ошибки системного provider не выводятся в
диагностику. Повторный выбор и submit отключены, пока выбор/декодирование
не завершены. После распознавания схемы не выполняются: допустимость профиля
определяет обычный импорт. HTTPS не получает привилегий источника OTA.

Проверки: 11 tests настоящих PNG/JPEG, поворота, инверсии, прозрачности, лимитов,
повреждённых входов, ложной решётки finder-pattern 512×512 и зависших file-provider
metadata/body/cancel; 4 widget tests подтверждения,
отмены, сохранения ввода и конкурентных действий. Нативный системный picker
проверяется отдельно в платформенных отчётах. Исходники:
[a88f75b](https://github.com/Extectick/ExVPN/commit/a88f75b).
Настоящие Android cancel → preview → Add → cold restart и Windows picker/cancel
с обезличенными снимками описаны в [ANDROID_VALIDATION.md](ANDROID_VALIDATION.md)
и [WINDOWS_VALIDATION.md](WINDOWS_VALIDATION.md). Полный Windows импорт ещё открыт.
