# Импорт подписки из QR

Состояние на 2026-10-16: QR читается из выбранного пользователем PNG/JPEG через
системный выбор файла Android/Windows. Камера и live scanning пока не реализованы.

В диалоге добавления подписки кнопка **«QR из изображения»** открывает выбор файла.
Результат появляется в поле для проверки. HTTPS выбирает режим ссылки; остальные
данные — режим текста. Чтение QR не обращается по найденному адресу и не меняет
подписки. Импорт выполняется существующим парсером/HTTPS-loader только после
кнопки **«Добавить»**. Отмена выбора или ошибка оставляет введённые данные.

Android использует собственный канал `exvpn/qr_import` и `ACTION_OPEN_DOCUMENT`.
Прежний `file_selector_android 0.5.2+11` читал и копировал весь URI до возврата
`XFile`, поэтому Dart-лимит не защищал от native allocation/ANR. Android QR больше
не вызывает этот путь. `ContentResolver.openAssetFileDescriptor` и чтение идут
в отдельном потоке; размер metadata не запрашивается и не задаёт размер буфера.
В cache файл не копируется, постоянное разрешение на URI не запрашивается.

Ограничения: 5 МиБ фактических данных (один дополнительный байт только для
обнаружения превышения); общий deadline 20 секунд после выбора URI покрывает
открытие, чтение и закрытие. При превышении времени UI получает фиксированную
ошибку; отмена provider и закрытие дескриптора выполняются отдельно от UI и друг
от друга. Одновременно разрешён один reader на процесс. Если provider игнорирует
отмену, его место остаётся занятым до реального завершения, включая зависший
cancel/close; повторы и пересоздание Activity не создают новые заблокированные
потоки. Уничтожение Activity отменяет запрос, поздние ответы не публикуются.
Системный picker не ограничен таймаутом и отменяется пользователем.

Windows и другие платформы сохраняют `file_selector`, затем ограниченное чтение
`XFile` с общим deadline 20 секунд на metadata/body; эти Dart-проверки сами по себе
не ограничивают работу плагина до возврата `XFile`.

Для обеих платформ: PNG/JPEG по сигнатуре;
каждая сторона не больше 4096 пикселей, суммарно не больше 4 Ми-пикселей;
один кадр; результат не больше 8192 символов, без NUL. Размеры проверяются
`ImageDescriptor` перед декодированием пикселей Flutter engine. Прозрачность
композируется на белый фон. ZXing читает обычный и инвертированный вариант;
на native декодирование QR выполняется через `compute`. Не больше 128 кандидатов
finder-pattern допускается до перебора троек ZXing: решётка ложных маркеров иначе
вызывает кубический рост работы даже на маленьком PNG. Превышение лимита выдаёт
«Изображение слишком сложное» без повторной инвертированной ветки. Ограничения
входа/растра/кандидатов не являются изоляцией нативного image codec или жёстким
таймаутом его CPU. На пути `XFile` при таймауте stream отменяется без ожидания потенциально зависшего
provider cancellation; поздние события игнорируются, накопленный буфер очищается.

Ни имя файла, ни содержимое QR, ни ошибки системного provider не выводятся в
диагностику. Повторный выбор и submit отключены, пока выбор/декодирование
не завершены. После распознавания схемы не выполняются: допустимость профиля
определяет обычный импорт. HTTPS не получает привилегий источника OTA.

Проверки: 11 tests настоящих PNG/JPEG, поворота, инверсии, прозрачности, лимитов,
повреждённых входов, ложной решётки finder-pattern 512×512 и зависших file-provider
metadata/body/cancel; 4 widget tests подтверждения,
отмены, сохранения ввода и конкурентных действий. Ещё 9 Flutter tests проверяют
Android MethodChannel, распознавание возвращённых байтов, отмену, фиксированные
ошибки и отсутствие fallback к прежнему picker. Все 24 Flutter tests прошли.
8 JVM tests проверяют фактический предел потока, отказ provider, зависшие
open/read/cancel/close, отмену Activity, удержание единственного worker и
подавление позднего успеха. Они прошли через `:app:testDebugUnitTest`; задача
добавлена в Android CI. Новая реализация: [fe48846](https://github.com/Extectick/ExVPN/commit/fe488467b9946b8f9ca79aad6d2a8bb777d25130).
Нативный системный picker новой сборки на API30 проверен: cancel, preview без
автоматического импорта, отказ 5 MiB + 1 byte и успешный повтор после ошибки.
На этом APK также повторён системный VPN permission и реальный VLESS TCP/HTTPS.
API36 нового picker и физическое устройство ещё открыты; подробности и хеши —
в [платформенном отчёте](ANDROID_VALIDATION.md). Исходники прежнего QR-потока:
[a88f75b](https://github.com/Extectick/ExVPN/commit/a88f75b).
Настоящие Android cancel → preview → Add → cold restart и Windows picker/cancel
с обезличенными снимками описаны в [ANDROID_VALIDATION.md](ANDROID_VALIDATION.md)
и [WINDOWS_VALIDATION.md](WINDOWS_VALIDATION.md). Полный Windows импорт ещё открыт.
